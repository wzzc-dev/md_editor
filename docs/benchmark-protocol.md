# Benchmark protocol

Each run uses `bench/run_benchmark.py` with the fixtures generated by
`scripts/generate_fixtures.py`. The harness uses the same three scenarios for
each adapter:

1. **open**: process launch plus fixture read and first render preparation.
2. **input**: insert ten ASCII characters at the end of the document and
   re-render after every character.
3. **scroll**: render 120 viewport positions at 60 Hz, moving by one viewport.

The runner records wall-clock samples in milliseconds. It reports mean, P95,
P99, dropped frames (`frame_ms > 16.667`), input latency and open startup
wall time. The JSON also
records OS release, CPU, memory, best-effort GPU (`GPU_MODEL` overrides probe),
renderer environment variables and toolchain versions. A command may
implement the machine-readable adapter protocol by accepting `--benchmark
<fixture> <scenario>` and printing one JSON object per line. Commands that are
not installed are explicitly marked `skipped`.

For a hardware run, provide commands with repeated `--adapter name=command`
arguments, for example:

```sh
python3 bench/run_benchmark.py \
  --adapter moui-skia-raster='moon run moui/benchmark --target native -- {fixture} {scenario}' \
  --adapter moui-skia-gpu='moon run moui/benchmark --target native -- {fixture} {scenario}' \
  --adapter gpui='cargo run --release --manifest-path gpui/Cargo.toml -- --benchmark {fixture} {scenario}' \
  --adapter flutter-skia='dart run flutter/tool/benchmark.dart {fixture} {scenario}' \
  --adapter flutter-impeller='dart run flutter/tool/benchmark.dart {fixture} {scenario}' \
  --adapter electron='npm run --prefix electron benchmark -- {fixture} {scenario}' \
  --out results/mac-arm64.json
```

The Dart adapter is a renderer-independent headless baseline. GUI Flutter
measurements should use the same fixture and scenario script while launching
the desktop app with `--no-enable-impeller` (Skia) and `--enable-impeller`
(Impeller), and should report `measurement_scope=ui-frame`.

The MoUI adapter prints two JSON objects per run: a `headless-render` row
(`split_blocks`, the cross-framework block-split baseline matching the
GPUI/Electron/Flutter splitters) and a `richtext-full` row
(`markdown_document`, MoUI's full rich-text preparation, capped at the small
fixture). `flutter/tool/benchmark.dart` executes the matching Dart block
splitter and reports `headless-render`. Use an instrumented desktop run and
`measurement_scope=ui-frame` before applying the acceptance threshold.

The report includes `platform`, `machine`, `cpu`, `memory_gb`, renderer and
all command lines. It is safe to compare only rows with matching fixture,
viewport, warm-up, repetition and `measurement_scope` settings.
