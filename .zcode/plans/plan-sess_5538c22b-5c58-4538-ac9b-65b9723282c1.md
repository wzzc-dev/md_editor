# MoUI Markdown 编辑器输入/打开路径优化计划

## 目标（stress fixture 实测基线 → 目标）

| 指标 | 当前 moui-md | 参照 | 目标 |
|---|---|---|---|
| input 延迟 | 180 ms | gpui 12.6 / Flutter 10 | **≤ 20–30 ms** |
| open 首帧 | 243 ms | Flutter 87 / gpui 136 | **≤ 120–150 ms** |
| scroll | 已达标（work 1.10 ms） | — | 不回退 |

决策（用户已确认）：① 输入路径直接改为**按块文本存储**，全串 source 降级为惰性物化视图；② 允许对 `moui/core/text_editing.mbt` 做保语义内部优化。

## 第 0 步：基线固化

先提交当前未提交的 shell-parse 成果（vendor/MoUI 8 个文件 + results/*，由用户自行提交或授权我提交），作为可回滚基线。

## 第 1 步：框架文本编辑原语优化（低风险，先行）

文件：`vendor/MoUI/moui/core/text_editing.mbt`（+ TextGraphemeBoundaries 所在文件）

1. `move_text_caret_index`（:108）与 `normalize_grapheme_range` 目前每键 `TextGraphemeBoundaries::new(text)` 全文建图素边界。改为**局部化**：只从目标 offset 向前/后各扫 ≤3 个码点定图素边界（UAX#29 边界规则只依赖邻近码点），提供 `grapheme_clamp_local(text, offset)`。
2. `replace_text_range`（:145）：`text_substring_by_char_range` 两次独立 `offset_of_nth_char` 全扫 → 用 `offset_of_nth_char(n, start_offset~)` 提示合并为一趟到 end 的扫描；重建仍一次 concat（5MB memcpy 本身 ~2ms，保留）。
3. `text_length` 的 `char_length()` 全扫：调用点缓存（control/session 已知长度则传 `length~`）。

预期收益：输入路径去掉每键 ≥3 次全文字符/图素扫描。验证：`moon test moui`（core 包）全绿 + 临时探针复测 input。

## 第 2 步：打开路径（与 rope 无关，独立提交）

文件：`moui_richtext/editor_source_mapping.mbt`、`editor_model.mbt`、`editor_session.mbt`

1. **偏移行视图**：`markdown_editor_lines`（editor_model.mbt）目前每行分配一个 String（stress 下 40 万次，探针 ~100ms）。改为返回 `(start,end)` 偏移对 + 分类器直接读 source 切片（shell 分类器已有 `markdown_editor_shell_slice` 形态，扩展其余调用点）。
2. **合并计数遍**：`markdown_document_session_from_blocks`（editor_session.mbt:2036）在 open（无 reuse）时分别跑 `word_count`、`line_count`、`block_source_line_counts` 三个全文遍 → 在 shell parse 的同一趟线性扫描中累计（shell 本来就逐字符扫），三个计数直接产出。
3. **廉价指纹**：`markdown_document_block_fingerprint` 从"kind 前缀 + 全文拼接 String"改为 `(kind, text.hash())` 的 UInt64/小结构，比较改 `==`；open 时指纹 = 内容哈希一遍（O(N) 但近乎免费），不再分配 10 万条指纹串。
4. **预分配**：shell parse 的 blocks / assigned / height-metrics 数组按行数上界 `with_capacity`，避免 10 万级 push 的倍增复制。

目标：stress open 243 → ≤150ms。验证：`moon test moui_richtext`（216）+ `moon test examples/markdown_editor/app`（417/423，6 个既有失败不增加）+ 单跑 open 场景计时。

## 第 3 步：按块文本存储核心（rope 数据层）

新文件：`moui_richtext/editor_text_store.mbt`

```
pub struct MarkdownDocumentTextStore {   // 可变共享，Ref 语义（GPUI 同款）
  mut block_texts : Array[String]        // 每块自己的文本
  mut block_deltas : ...                 // 或直接用 blocks[i].source_range 派生偏移
  revision : Ref[Int]
  materialized : Ref[String?]            // 全串缓存
}
fn materialize(store) -> String          // 有缓存即返回；否则 StringBuilder 一次拼接
fn edit(store, range, replacement)       // 定位受影响块（≤2 块合并区间）→ 只重写这些块的 String → 其余块 range 平移 delta → revision+1，缓存失效
```

- `MarkdownDocumentSession` 增加 `text_store` 字段；`source : String` 字段改为**惰性物化属性**（所有现有读路径——find、save/export、source_mode、caret——语义不变，行为零变化，只是不在每键更新）。
- `markdown_editor_block_materialized`（editor_source_mapping.mbt）从"按 source_range 切全串再 parse"改为**直接用 store 的块文本**——materialize 不再依赖全串。
- 每键全流程从此不触碰 5MB 字符串；全串只在 save/export/undo/查找可见时物化（各一次，缓存住）。

验证：现有 216+423 测试全绿（读路径语义不变是本步的验收线）。

## 第 4 步：输入路径接入 store（每键 O(编辑块)）

1. **事务携带编辑区间**：`RichTextInputTransform` 增加 `edit : (start, end, String)?`；框架控件在产生 transform 时本来就知道 range+replacement，示例 app 的 `apply_text_transform`（editor_state_edits.mbt:77）改走新的 `MarkdownEditTransaction::from_edit(...)`，彻底删除 `from_sources` 的前缀/后缀 diff + 双 `char_length`（editor_session.mbt:138-230）。`from_sources` 保留给 undo/undo-like 路径。
2. **`markdown_document_session_apply_incremental`**（editor_session.mbt:584）：`transaction.source` 的全部读取（deleted 子串、region_slice、stitch 后校验）改读 store；stitch 采用 **GPUI 原地复用模式**（gpui/adapter/app.mbt:86-135 先例：块数不变时数组原地改写、`heights[i] = …`，每键零分配）——`editor_blocks`/`blocks`/height metrics 三个 100k 数组不再每键重建，后缀平移原地改 `source_range`，session 值仍按 revision+1 重建为轻记录。
3. **撤销复用事务区间**：`record_edit_history`（editor_state_edits.mbt:330）不再 `text_history_delta(before, after)` 全文 diff，直接用事务的 `(edit_range, deleted, replacement)` 造 delta；undo/redo 的 restore 走 `replace_source` 整文档重建（非基准路径，接受 O(N)）。
4. **缓存键去全文**：`markdown_editor_blocks_cache`（rich_text_cache.mbt:436，5MB 源串当 Map key）→ 热路径删除，blocks 数组直接由 store/session 持有；definitions cache 的 `(length, digest)` 键在增量 apply 里改为 `(length, revision)`（增量安全守卫已证明定义集不变，不再算全文 digest）。
5. 视口/光标的 `rich_text_window` 已是窗口化（editor_session.mbt:388），不改。

验证：`moon test moui_richtext` + 示例 app 测试；新增热路径计数器测试（每键 source 物化次数=0、窗口外指纹构建=0）；临时计时探针复测 input 后移除。

## 第 5 步：复测与报告

1. 重编译 `moon build moui/benchmark --target native --release`。
2. `bench/run_benchmark.py` 跑 `moui-md-skia-raster/gpu、moui-md-wgpu、gpui` × 4 fixture × open/input/scroll × 3 重复（协议同 `scripts/run_ui_benchmark.sh:83-101`），`bench/report.py` 出 md；与 `results/macos-arm64-ui.json` 基线对比，确认 small/medium/large 无回退。
3. `sample`/xctrace 抽查：每键分配次数应从万级降到个位数。
4. 若 input 仍 >30ms 或 open >150ms，用计时探针定位残余，另立跟进项（候选：把 indent/task/link 等低频命令也迁到 store 编辑；materialize 增量化）。

## 风险与守护

- **原地数组 vs 值语义**：layout cache / 测量高度表已按 `(block_id, revision)` 键控（editor_session.mbt:1344），原地改写 + revision bump 天然失效，无脏读；undo 栈只存文本 delta 不存 session，安全。
- **回滚**：每步独立 commit；`replace_source` 全壳重建路径全程保留为 fallback。
- **既有 6 个测试失败**（contextual palette ×5 + dirty_layout_count ×1）为先前遗留，本计划不新增失败即为达标。
