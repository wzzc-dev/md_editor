## 目标

把上轮分析出的两个桥协议缺口补上（velotype 行为对齐，编辑内核留在 MoonBit）：

1. **文本行布局度量回读**——点击定位从"段内线性插值"升级为逐字符精确（比例字体下也精确）。
2. **光标声明 + Rust 侧绘制**——光标不再是树里的 2px div，而是命令缓冲里对文本节点的一行声明，由 Rust 在 paint 期从真实布局算矩形画 quad，附带 velotype 同款闪烁（0.5s 常亮 + 余弦淡出）。

级别 3（真 IME EntityInputHandler 管线）和上下键像素粘滞列**不在本次范围**，作为后续项。

改动落在两个仓库：`gpui/third_party/gpui-moonbit`（子模块：gpui-sys + moonbit-bindings，下一个空闲 opcode = 41）和 `gpui`（adapter）。子模块内提交后在 gpui 仓库 bump 指针。

## 协议设计

### A. 度量回读（mirror-then-pull，完全复刻 gpui_probe_rect 形态）

- Rust：渲染 `UiNode::Text` 时（4613-4652 的 arm），给有 key 的文本节点套一个透明 wrapper 元素（照 `ProbeBoundsProbe` 3290-3367 的写法），prepaint 时把 `styled.layout().clone()`（Rc，便宜）写进新表 `TEXT_METRICS: Mutex<Option<HashMap<String, TextLayout>>>`，随现有 `"probe:clear"` 每帧清空。shipped 构建里已有先例：`TextInputModel.last_layout` + `x_for_index`/`index_for_x`（2603/2864/2882）；测试专用 stash（4884）即概念验证。
- 新导出（`ffi_export` 包裹，导出测试 7488 强制）：
  - `gpui_text_x_for_char(key, key_len, char_idx, out) -> i32`：out = 2×LE i32（x、y，1/4px 定点，含软折行行号）；命中 0，miss -1。
  - `gpui_text_char_for_position(key, key_len, x, y, out) -> i32`：out = 1×LE i32 字符下标。
  - **字符下标口径**（非字节）：Rust 内部用 `char_indices` 与 gpui 布局的字节索引互转（行短，O(n) 无所谓），与 MoonBit 模型单位一致。
- 消费端声明按 `gpui_probe_rect` 的既有模式：手写在 `adapter/hit.mbt`（不跑 bindgen 管线），`#borrow` + 预零 `Bytes` out。

### B. 光标声明

- `abi.toml` 新增 `OP_SET_CARET = 41`（两侧常量文件均自动生成），wire：`byte_offset u32 | rgba u8×3 | blink u8`；byte offset 由 bindings writer 在富文本内容上完成 char→byte 转换。作用于**栈顶文本节点**（`rich_text` 之后、`add_child` 之前调用）。
- Rust：`UiNode::Text` 增 `caret: Option<CaretSpec>`；渲染时套 `CaretProbe` 元素——prepaint 用布局算 `position_for_index(byte_offset)` 得 caret rect（`TextInputElement` 3032-3041 的 `fill(Bounds::new(...), color)` + 3082-3090 `paint_quad` 就是现成模板），同时把该矩形写入 `PROBE_BOUNDS["caret"]`，**ImeBridge 的候选锚（3507-3531）零改动继续工作**。
- 闪烁：桥内无计时器先例，用已验证的 `window.on_next_frame` 自续链 + `window.refresh()`（benchmark 2262-2267 的注释就是这个坑）：树中存在 blink=1 光标时挂链；`build_tree` 提交含 caret 的树即重置 blink epoch（打字/移动/点击都会重建 → 语义与 velotype 输入重置一致）；可见性 = 0.5s 全亮后 cos 淡入淡出；无光标自动停链。
- preedit（输入法组合中）维持现有 overlay div 整支不动，此时不发 caret 声明（避免双光标）。

**第 1 步：子模块 gpui-sys（Rust）**
- `abi.toml` + decoder arm（OP_SET_CARET）+ `UiNode::Text` 字段 + wire 布局注释更新（823-840）。
- `TextMetricsProbe`/`CaretProbe` 元素 + `TEXT_METRICS` 表 + 两个 pull 导出（含 `include/gpui_sys.h` 重生成）。
- 闪烁循环；`fuzz_tests.rs` 操作数字典加 41；`headless_tests` 加 caret/metrics 往返测试。
- 实现起点先对着 `~/.cargo/registry` 里 gpui 0.2 的 `LineLayout` 核实 `x_for_index`/`position_for_index`/`index_for_position` 的确切签名（本计划唯一 API 不确定点）。

**第 2 步：子模块 moonbit-bindings**
- 重新生成 `abi_constants.mbt`/`.rs`（build.sh 自动）；`gpui-bindings.mbt` 加 `set_caret(byte_offset, r, g, b, blink)`（char→byte 转换在 writer）；`moon info` 刷 mbti；新增 wire 字节级 wbtest（仿 OP_TEXT_RUN 冻结测试）+ fuzz 表联动。

**第 3 步：adapter（gpui 仓库）**
- `render.mbt`：光标所在行不再为光标劈段——**探针段固定每行一段**（starts 表反而变简单）；纯文本态删除 `caret_overlay`，改为在光标行 text 节点上调 `cb.set_caret(...)`；删除非末行的视觉尾区 div；`tail_zone` 保留（点击语义 + IME 无关）。
- `hit.mbt`：`caret_at_point` 增加注入的 metrics 函数参数；命中行/段后在段字符区间内**二分查询**逐字符定列；metrics 返回 None（headless/未 paint）时回退现有线性插值——`hit_wbtest` 用假 metrics 注入测试，不触 FFI。
- 测试更新：`hit_wbtest` 的 starts 断言去掉劈行（如 [0,12,16,26,27] → [0,12,26,27]）、新增逐字符命中用例；`render_wbtest` 扫 OP_SET_CARET wire；`selftest` 光标场景改断言。
- gpui 仓库 bump 子模块指针。

## 验证

1. `cargo test`（子模块）+ bindings 包独立 `moon test` + `gpui/` 下 `moon test`（core+adapter）+ `moon run selftest` 全绿。
2. `bench/adapters/gpui/build.py` 全量构建，启动窗口手工验证三场景（段中行中 / 行尾 / 代码块行中与行尾）：光标逐字符精确、闪烁生效、代码块点击列精确、输入法组合正常、候选窗位置正常。
3. gpui 适配器 open/input/scroll 基准回归——预期 frame_work 无显著变化（每行多一次 Rc clone + 一个 quad），有回退则把 metrics 记录限制为"本帧被查询过的 key"或仅光标行。

## 风险与对策

- **gpui 0.2 布局 API 签名**：实施第一步即核实，若 `TextLayout` 无直接 `x_for_index`，退路是逐行 `Line` 级 `ShapedLine::x_for_index` + 行表定位（velotype 的 WrappedLine 就是这层做法）。
- **rich_text 内部软折行**：metrics 输出含 y，caret 与命中都天然处理多视觉行；比现在的劈段方案更正确。
- **闪烁空转**：blink 链严格以"本帧存在 caret 声明"为条件启停。
- **协议兼容**：老 buffer 不含新 opcode 不受影响（版本不变）；新 buffer 在老 Rust 上会以 `UNKNOWN_OPCODE(-7)` 显式失败——两侧同一子模块同批提交，无错配窗口。
